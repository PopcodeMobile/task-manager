## Exact additive contracts and cost

Migration `supabase/migrations/202610200009_task_context_execution.sql` SHA-256:

`107140f3a400221adc6962e36c0670a07603e07598f9e54f296d38cdf37a428e`

Migrations001–008 are unchanged.009 adds `tasks.execution_state` (`running|blocked|null`) and `blocking_reason`; a check requires nonblank1–2000character reason exactly when blocked, otherwise null. Private validation/task/read predecessor functions are renamed and kept inaccessible to public/anon/authenticated. Current005 transaction implementation is redefined to carry execution through the same authority, workspace lock, CAS, rate, receipt and event transaction. Existing006–008 wrapper validation chain remains delegated. The enqueue function's unreachable workflow-status classifier is replaced with execution-state classification; its delivery body stays minimal. No dependency change.

**I1 read.** MCP `get_task({workspace_id,id,context?,limit?,cursor?})`; HTTP `GET /v1/workspaces/{workspace_id}/tasks/{id}` accepts the corresponding context/paging query. Supported context values: `comments`, `subtasks`, `dependencies`, `files`, `attachments`. No context gives the backward-compatible `{data:Task}` envelope (Task gains additive execution projection). With context: `{data:Task,context:{kind,items,nextCursor}}`. Default limit50, maximum100; `nextCursor:null` means that current page exhausted the selected family. Treat non-null cursor as opaque and replay unchanged. Its internal JSON is `[workspaceId,taskId,context,innerCursor]`; mismatched/null bindings are rejected. This is current keyset paging, not a frozen transactional snapshot across pages. Deleted comments disappear; `authorUserId` is nullable and no fabricated human identity is substituted. Files include direct task files and files linked through current attachments, deduplicated by file row. Attachment records identify their files; no uploaded bytes are exposed.

Context delegates current normalized reads for all families except files. It consequently consumes two existing quota units per delegated context page (outer authority and existing scoped read); files consumes one. This is explicit cost, not a quota change. Cursor malformed-input errors remain sanitized. Relation families beyond this approved context were not added to MCP.

**I2 command.** Existing `renew_task_claim` input adds optional `executionState:'running'|'blocked'` and `blockingReason:string`. Existing `id`, live `claimToken`, expectedVersion and idempotency key still apply. Blocked requires nonblank reason≤2000; reason without blocked is rejected. Explicit running clears reason; omitted fields preserve state/reason. Read projection is `execution:null|{state,reason,active}`. Active depends on valid current reservation and live agent/member/client/connection/grant/consent authority. Expired or revoked execution may remain visible as previous state but `active:false`; release/complete/human intervention clear current projection, and a new claim starts running without the old reason. Audit retains history.

A real change to blocked state or its reason sets `executionState:'blocked'` on the transactional domain event and classifies `task.run_blocked`; unchanged blocked renewal and omitted-state renewal do not enqueue another blocked event. Other normal command audit events remain. Receipt replay returns the prior result without duplicating effects, after the existing current-authority checks. Workflow status remains backlog/todo/progress/review/done. The supervision UI displays reason, with active versus previous execution wording.

**I3 read/paging.** HTTP `GET /v1/workspaces/{workspace_id}/event-cursor`, repository `query('get_event_cursor',{},true)` returns `{data:{cursor}}`; no thirteenth MCP tool. Authorized workspace/grant and existing quota apply. Current high-water is the maximum existing event cursor; empty workspace uses `["", ""]`. Capture happens before mutable graph hydration. Poll and post-command event reads request at most one100row page per request. Initial snapshot sets `historyComplete:false` and does not exhaust comments/reactions/activity/events. On-demand task discussions use scoped comments, task-scoped reactions (joined through current comments), and task events. Inbox, drawer, workspace history and search show continuation/retry. Search's “no results” is qualified while further relevant pages exist; each continuation applies the current search to accumulated results. Complete supplied arrays, including empty arrays, still avoid duplicate reads; undefined/partial requires reads. Failed continuation preserves cursor and rows; failed refresh preserves its reset parameters for retry. Revisions refresh first pages and expose continuation again.

This bounds request count attributable to history during opening; it does not promise a production latency SLO, bounded total graph size, simultaneous-tab quota independence or unlimited paging within a minute. Quota240, batch100, payload262144, original102task fixture, strict sanitizer, authority-before-receipts and legacy migration boundaries are unchanged. High-water SQL is one request; no query-plan/large-database latency benchmark was run.
