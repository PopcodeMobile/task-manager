## Directly introduced breakage

### N3 — Minor / P3: Local member history can show activity metadata for a hidden private project

**Changed source:** `src/app/activity/ContextHistory.tsx:61–67`, reached by new `PeoplePages.tsx:307`.

**Trigger:** In the local demo, a member has an `update_project` event for a private project that the current local actor cannot see. The member page receives a visibility-filtered snapshot, but its new ContextHistory independently queries raw `list_domain_events`. Local `appendEvent` (`src/workspace/local-panel.js:395–413`) represents an update_project input `{id: privateProjectId, ...}` with entityId equal to that project ID and no payload.projectId/taskId. ContextHistory only checks payload.projectId or a referenced task's project; neither exists in this shape, so the hidden project event passes its member filter.

The existing `visiblePanelSnapshot` (`panel-model.ts:69–72`) explicitly excludes hidden project entity IDs, but its already-filtered `snapshot.events` cannot filter the independently fetched historical page. Before this change the member surface only rendered visibility-filtered legacy activity and did not independently display these domain events.

**Actual visible information:** `ActivityPage.tsx:63–78` displays the actor name (or generic Member), the translated action “updated a project”, and timestamp. It does **not** render the hidden project's name, ID, body, task title or a project link for this shape. This is local-demo visibility parity, not evidence of cloud cross-tenant access, OAuth bypass or a remote data disclosure. Severity is therefore minor/P3.

**Reviewer probe:** Executed exactly one isolated in-memory probe using the actual ContextHistory and actual usePagedCollection through the existing JSX/state/effect shim. The repository fixture returned the source-supported local event shape; the visible snapshot contained only a different public project. Output:

```json
{"probe":"new local member history hidden-project event","visibleProjectIds":["public-project"],"fixtureEvent":{"id":"hidden-event","operation":"update_project","entityId":"private-project","actorUserId":"member","actorAgentId":null,"createdAt":"2026-10-21T00:00:00Z","payload":{}},"renderedEvents":[{"id":"hidden-event","operation":"update_project","entityId":"private-project","actorUserId":"member","actorAgentId":null,"createdAt":"2026-10-21T00:00:00Z","payload":{}}]}
```

The probe establishes that the actual component passes the hidden event to ActivityPage. The exact text rendering and producer shape were traced in source; no new browser/local-adapter end-to-end run is claimed.

**Smallest correction if root elects to fix:** Apply the existing local visibility policy to independently fetched domain pages as well, including project entity IDs when payload.projectId is absent. Supply enough entity visibility context or classify these project-scoped operations against visible project IDs. Retain legitimate workspace/member events without project associations. A focused assertion using the above hidden-project shape, plus one visible project and one unscoped event, would verify the correction without another broad suite.
